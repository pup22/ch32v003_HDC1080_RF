# CH32V003 + HDC1080 + OOK: беспроводные датчики температуры и влажности

Автономный датчик на микроконтроллере **CH32V003** (RISC-V, 16 КБ флеш). Примерно раз в 9 минут просыпается, измеряет температуру и влажность датчиком **HDC1080**, измеряет собственное напряжение питания и отправляет данные по радиоканалу (ASK/OOK) в формате **RadioHead RH_ASK**. Остальное время проводит в глубоком сне (Standby с автопробуждением), ток сна всей схемы около 10 мкА.

Передатчиков может быть несколько: каждый имеет свой номер, а приёмная часть на **ESPHome** (ESP8266/ESP32) разносит данные по отдельным сенсорам в Home Assistant.

Проект построен на [ch32fun](https://github.com/cnlohr/ch32fun) без SDK производителя.

## Возможности

- Температура и влажность с HDC1080 (программный I2C, без аппаратного периферийного блока).
- Измерение напряжения питания через внутренний источник Vrefint (АЦП).
- Пакет RH_ASK: 4-to-6 кодирование, CRC-16, 2000 бит/с. Принимается стандартной библиотекой RadioHead и компонентом ESPHome из этого репозитория.
- Номер передатчика в заголовке пакета (FROM) и счётчик пакетов (ID): можно использовать несколько передатчиков на один приёмник и отбрасывать повторы.
- Датчик и передатчик получают питание от пинов/ключа и обесточиваются между измерениями.
- Сон Standby + AWU от LSI, неиспользуемые пины в «тихом» состоянии.
- Защита от зависаний: все ожидания в АЦП и при запуске LSI с таймаутами.
- Компонент ESPHome: несколько передатчиков, тайм-аут молчания, все уровни логов.

## Железо

| Компонент | Описание |
|---|---|
| MCU | CH32V003, тактирование HSI 24 МГц, делитель HCLK/8, то есть 3 МГц |
| Датчик | HDC1080 (модуль или микросхема), адрес I2C `0x40` |
| Передатчик | дешёвый OOK-модуль (FS1000A и подобные).  |
| Ключ | PNP-транзистор для отключения питания передатчика |
| Питание | 3 - 4.2 В , MCU и передатчик на одной шине |

### Распиновка

| Пин MCU | Назначение |
|---|---|
| `PC1` | SCL датчика |
| `PC2` | SDA датчика |
| `PC3` | VCC датчика (питание с GPIO) |
| `PC4` | GND датчика (земля через GPIO) |
| `PC0` | DATA передатчика |
| `PA2` | База PNP-ключа питания передатчика (через резистор) |
| `PA1`, `PC5`-`PC7`, `PD0`-`PD7` | не используются: вход с подтяжкой к плюсу |

Датчик питается от пинов PC3/PC4 и подключается только на время измерения. Передатчик питается через PNP-ключ.

### Схема питания передатчика

```
+5V ──────┬───────────────┐
          │ E             │
   PA2 ─[R 4.7k]─ B  PNP  │
          │ C             │
          └──────── VCC ──┤ Модуль
   PC0 ───────────── DATA ┤ передатчика
   GND ───────────── GND ─┘
```

- `PA2 = LOW`: ключ открыт, передатчик включён. `PA2 = HIGH`: ключ закрыт.
- Рекомендуется резистор ~10 кОм между базой и эмиттером PNP, чтобы ключ надёжно закрывался, пока пин не сконфигурирован или находится в Hi-Z.
- Подтяжки SDA/SCL должны идти к **VCC датчика** (PC3), а не к постоянной шине, иначе во сне они будут питать обесточенный датчик через защитные диоды.
- Рядом с передатчиком желательно поставить конденсаторы 100 нФ и 47-100 мкФ: просадка питания во время передачи сдвигает частоту внутреннего RC-генератора.

## Структура проекта

| Файл | Назначение |
|---|---|

| `sleep.c` | Сон Standby + AWU (одно окно ~30 с), защита от незапуска LSI |
| `hdc1080.c/.h` | Драйвер HDC1080 (bit-bang I2C), отбраковка недостоверных данных |
| `ook_tx.c/.h` | Передатчик OOK, формат RH_ASK |
| `adc_vdd.c` | Измерение VDD по Vrefint, АЦП включается только на время замера |
| `funconfig.h` | Конфигурация ch32fun (HSI, без PLL, 3 МГц, DebugPrintf выключен) |
| `esphome/` | Приёмный компонент ESPHome `radiohead_ask`, пример конфигурации и тесты для ПК |

## Работа прошивки

Цикл работы (около 0,4 с активной фазы):

1. Измеряется напряжение питания (датчик и передатчик ещё выключены).
2. Включается питание датчика, через 15 мс читаются температура и влажность (ожидание конверсии 20 мс). Данные с `0xFFFF` в температуре или нулями в обоих полях считаются недостоверными.
3. Включается передатчик, отправляются **3 одинаковых пакета** с одним ID. Пауза между ними `15 + (id_transmitter % 8) * 7` мс: у разных передатчиков она разная, чтобы два одновременно включённых устройства не накладывались всеми тремя повторами.
4. Датчик и передатчик обесточиваются, линии I2C получают подтяжку к земле.
5. 15 раз подряд выполняется `sleep_30s()` (Standby, пробуждение по AWU).

Интервал между измерениями: номинально 15 × 30,72 с ≈ 7,7 мин. Реальный период зависит от экземпляра чипа (разброс LSI): у автора каждый шаг сна около 34 с, то есть интервал около 8,5 мин. Подгоняйте число повторов `sleep_30s()` в `main.c` под измеренный период.

При ошибке датчика пакет всё равно отправляется: температура и влажность равны `0xFFFF`, напряжение питания верное. Если LSI не запустился, `sleep_30s()` просто ждёт 30,72 с без сна, и прошивка не зависает.

### Номер передатчика

В начале `main.c`:

```c
const static uint8_t id_transmitter = 0x01;
```

У каждого передатчика **свой** номер, от 1 до 254 (0 и 255 не использовать: 255 это широковещательный адрес). Номер попадает в поле FROM пакета, и по нему приёмник определяет, чьи это данные.

## Формат пакета

Полезная нагрузка 6 байт, порядок байт big-endian:

| Байты | Поле | Тип | Единицы |
|---|---|---|---|
| 0-1 | Температура | `int16_t` | °C × 100 |
| 2-3 | Влажность | `uint16_t` | %RH × 100 |
| 4-5 | Напряжение питания | `uint16_t` | мВ |

Признак отказа датчика: байты 0-3 равны `0xFF`.

Радиокадр RH_ASK: преамбула 6 × `0x2a`, стартовые символы `0x38 0x2c`, байт длины (`len + 7`), заголовки, данные, CRC-16 (CCITT, инвертированный, младший байт первым). Бит 500 мкс (2000 бит/с), пакет занимает около 102 мс.

Заголовки:

| Поле | Значение |
|---|---|
| TO | `0xFF` (широковещательный) |
| FROM | `id_transmitter` |
| ID | счётчик пакетов, растёт на 1 за измерение, все три повтора с одним ID |
| FLAGS | `0x00` |

## Сборка и прошивка

Нужны [ch32fun](https://github.com/cnlohr/ch32fun) и прошивальщик (`minichlink`, WCH-LinkE, ESP32-S2 swadge и т. п.). Поместите проект в каталог примеров ch32fun или подключите ch32fun в вашем `Makefile`, затем:

```sh
make
make flash        # или: minichlink -w main.bin flash -b
```

Выбор чипа (`CH32V003`) задан в `funconfig.h` и `Makefile`.

### Важно: окно для перепрошивки

В режиме Standby отладочный интерфейс отключён, и прошить чип в спящем состоянии нельзя. Поэтому после запуска пины переводятся в безопасное состояние, затем идёт `Delay_Ms(5000)`. Прошивайте сразу после подачи питания или сброса, в течение этих 5 секунд.

Пин `PD1` (SWIO) в текущей версии входит в список неиспользуемых пинов и после окна переводится в GPIO. Это осознанный выбор: прошить можно только в первые 5 секунд после подачи питания. Если нужен доступ программатора в любое время, уберите `PD1` из массива `unused[]`.

## Приём в ESPHome (основной вариант)

Компонент `radiohead_ask` лежит в `esphome/components/radiohead_ask/`. Он сам декодирует RH_ASK по длительностям импульсов, библиотека RadioHead не нужна. Работает на ESP8266 и ESP32. Подключается к отдельному пину приёмника (на нём не должно быть другого `remote_receiver`).

```yaml
external_components:
  - source:
      type: local
      path: components

radiohead_ask:
  pin: GPIO05           # DATA приёмника
  bit_rate: 2000        # должен совпадать с BIT_PERIOD_US = 500 в ook_tx.c
  transmitters:
    - transmitter_id: 1 # = id_transmitter в прошивке
      timeout: 30min    # необязательно: после молчания значения становятся «неизвестно»
      temperature:
        name: "Температура"
      humidity:
        name: "Влажность"
      voltage:
        name: "Напряжение батареи"
    - transmitter_id: 2
      timeout: 30min
      temperature:
        name: "Температура 2"
      humidity:
        name: "Влажность 2"
      voltage:
        name: "Напряжение батареи 2"
```

Что делает компонент:

- Разносит данные по передатчикам по полю FROM. ID пакета у разных передатчиков может совпадать.
- Отбрасывает повторы (одинаковый ID от того же передатчика в течение 2 с).
- Пакет от передатчика, которого нет в конфигурации, не теряется молча: один раз выводится предупреждение с нужным `transmitter_id`.
- При отказе датчика на передатчике температура и влажность становятся «неизвестно», напряжение публикуется.
- Отбрасывает невозможные значения и напряжение вне 1,5-6,5 В.
- Если передатчик молчит дольше `timeout`, его значения сбрасываются, а компонент выставляет предупреждение статуса.

Уровни логов:

| Уровень | Что выводится |
|---|---|
| ERROR | неверная конфигурация, компонент не запущен |
| WARN | неизвестный передатчик, неверная длина, недопустимые значения, отказ датчика, тайм-аут, переполнение буфера |
| INFO | запуск, передатчик появился на связи |
| CONFIG | параметры и сенсоры каждого передатчика |
| DEBUG | значения каждого измерения, ошибки CRC, статистика раз в 5 минут |
| VERBOSE | заголовки пакетов, пропущенные повторы, ложные старты |
| VERY_VERBOSE | hex-дамп данных пакета |

Для работы удобно `logger: level: INFO`, а отладку включать точечно: `logs: radiohead_ask: DEBUG`.

Подробности, структура папок и тесты для ПК: `esphome/README.md`.

## Приём в Arduino (RadioHead)

```cpp
#include <RH_ASK.h>
#include <SPI.h>

RH_ASK driver(2000, 11, 12, 10);   // скорость 2000 бит/с, RX = D11

uint8_t last_id[256];              // последний принятый ID для каждого передатчика
bool have_id[256];

void setup() {
  Serial.begin(115200);
  if (!driver.init()) Serial.println("RH_ASK init failed");
}

void loop() {
  uint8_t buf[RH_ASK_MAX_MESSAGE_LEN];
  uint8_t len = sizeof(buf);

  if (driver.recv(buf, &len) && len == 6) {
    uint8_t from = driver.headerFrom();
    uint8_t id = driver.headerId();
    if (have_id[from] && last_id[from] == id) return;   // повтор того же измерения
    have_id[from] = true;
    last_id[from] = id;

    uint16_t v = (uint16_t)((buf[4] << 8) | buf[5]);
    Serial.print("#"); Serial.print(from);
    if (buf[0] == 0xFF && buf[1] == 0xFF && buf[2] == 0xFF && buf[3] == 0xFF) {
      Serial.print(": датчик не ответил");
    } else {
      int16_t  t = (int16_t)((buf[0] << 8) | buf[1]);
      uint16_t h = (uint16_t)((buf[2] << 8) | buf[3]);
      Serial.print(": T="); Serial.print(t / 100.0);
      Serial.print(" C, RH="); Serial.print(h / 100.0); Serial.print(" %");
    }
    Serial.print(", VDD="); Serial.print(v); Serial.println(" mV");
  }
}
```

Дедупликация по ID сбросится, если перезагрузить передатчик и счётчик начнётся заново; для бытового применения этого достаточно.

## Энергопотребление

- Сон Standby + AWU: измерено около **10 мкА** для всей схемы (MCU, датчик и передатчик обесточены).
- Активная фаза около 0,4 с на цикл. Её вклад определяет передатчик (три пакета по ~102 мс); ток модуля зависит от конкретной модели, поэтому оценивайте средний ток по собственному измерению.
- Что дало малый ток сна: все неиспользуемые пины в вход с подтяжкой, подтяжки I2C к земле при обесточенном датчике, PNP-ключ с резистором база-эмиттер, измерение без подключённого программатора.

## Известные ограничения

- Расчёты температуры и влажности выполняются во float (подключается soft-float, несколько КБ флеша). Возможный переход на целые числа.
- Тайминг бита задаётся `Delay_Us(500)` плюс запись через `funDigitalWrite`, поэтому бит чуть длиннее 500 мкс. Приёмная часть к этому допуску устойчива (проверено на ПК при отклонении бита ±3 %), но реальную длительность стоит измерить логическим анализатором.
- Ответ на конфигурацию HDC1080 не проверяется. Если датчик не ответит, отказ выявляется при чтении (нет ACK или недостоверные данные).
- Напряжение питания измеряется до включения датчика и передатчика, то есть без нагрузки; под нагрузкой передачи оно ниже.
- Нет проверки минимального напряжения питания для HDC1080 (2,7 В).
- Интервал сна зависит от LSI и меняется от экземпляра к экземпляру; его нужно подгонять измерением.
- Два передатчика, передающие одновременно, всё равно могут потерять часть пакетов (наложение в эфире). От этого защищают три повтора с разной паузой, но не гарантированно.
